# Настройки сервера: секретный ключ, режим отладки, резервные копии

Всё ниже делается один раз на сервере, в папке проекта (там, где `manage.py`).

## 1. Секретный ключ и выключенная отладка

Сейчас секретный ключ лежит прямо в коде, а режим отладки включён. Это значит, что при любой
ошибке посетитель сайта видит технические подробности: куски кода и настройки. Исправляется
файлом `.env` — в git он не попадает.

Создайте новый ключ:

```bash
python -c "import secrets; print(secrets.token_urlsafe(50))"
```

Создайте файл `.env` рядом с `manage.py`:

```env
DJANGO_SECRET_KEY=сюда-ключ-из-команды-выше
DJANGO_DEBUG=0
```

Перезапустите сайт. После смены ключа всем придётся один раз войти заново — это нормально.

Если что-то пошло не так, поменяйте `DJANGO_DEBUG=0` на `DJANGO_DEBUG=1` и перезапустите — станет
как раньше. Фото, книги и логотип CRM раздаёт сама, поэтому без отладки они не пропадут.

## 2. Резервные копии базы каждый день

Все ученики, группы, уроки и оплаты лежат в одном файле `db.sqlite3`. Если сервер сломается или
файл повредится — без копии всё пропадёт.

Ручная копия (проверить, что работает):

```bash
python manage.py backup_db
```

Копия появится в папке `backups/`, хранятся последние 30.

Каждый день в 3 ночи — откройте расписание командой `crontab -e` и добавьте строку
(путь к проекту и к python замените на свои; узнать их — команды `pwd` и `which python`):

```cron
0 3 * * * cd /путь/к/english-center-crm && /путь/к/python manage.py backup_db >> backups/backup.log 2>&1
```

Копия на том же сервере не спасёт, если сломается сам сервер. Поэтому раз в неделю скачивайте
копию к себе: «Профиль» → «Скачать копию базы» (у админа), или через поиск Ctrl+K → «Скачать копию базы».

## 3. Как восстановить базу из копии

1. Остановите сайт.
2. Сохраните текущую базу на всякий случай: `cp db.sqlite3 db.sqlite3.broken`
3. Положите копию на её место: `cp backups/db-20261016-0300.sqlite3 db.sqlite3`
   (или скачанный файл `enjoy-english-….sqlite3`).
4. Запустите сайт.
